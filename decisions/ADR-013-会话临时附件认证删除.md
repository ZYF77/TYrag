# ADR-013：会话临时附件认证删除

## 状态

已采纳，对应 RF-PATCH-006。

## 背景

RAGFlow v0.26.4 的 `POST /api/v1/documents/upload` 把运行时附件写入认证 tenant 的 downloads bucket，但没有单对象删除 API。Gateway 直接访问 RAGFlow `STORAGE_IMPL` 会越过服务边界，删除整个 session 又会破坏后续会话与历史。

## 决策

- 增加认证的 `DELETE /api/v1/documents/upload/{file_id}`，只删除一个运行时 upload。
- `file_id` 必须是上传接口生成的 32 位小写十六进制 ID。
- bucket 只能由 RAGFlow 根据认证 tenant 计算为 `{tenant_id}-downloads`；请求不得提供 bucket、用户或对象路径。
- 删除语义幂等，返回目标 ID；它不是通用文件管理 API。
- Gateway 只调用该 HTTP API，不再导入或探测 RAGFlow 内部 storage。
- 正常 completion 结束后立即请求删除；失败对象由现有 ledger 在 TTL 后重试。

## 回滚

先回退 Gateway 的 DELETE 调用，再撤销 RF-PATCH-006。已经删除的临时附件不恢复；FILE_SHARE 文档、业务历史和 EAM 协议不受影响。
