# ADR-005 解析质量评测与门禁

## 状态
Accepted

## 背景

WP-02 已打通 MinIO -> Gateway -> Outbox/Worker -> RAGFlow -> ready 的同步链路，
WP-04/WP-05 已验证真实问答。WP-03 Phase 1 需要把验收重点从“链路是否可用”转向
“解析结果是否可衡量、可复核、可验收”。

RAGFlow 的 `run=DONE` 只表示任务完成，不代表文本、页码、坐标、表格或关键字段
达到业务可检索质量。因此必须设计独立于 `sync_status` 的 `parse_quality_status`。

## 决策

1. 新增 `contracts/parse-quality-evaluation.md` 作为解析质量评测契约，不改动
   `contracts/metadata-schema.json`、`contracts/status-state-machine.md` 或
   `contracts/integration-openapi.yaml`。
2. `parse_quality_status` 取值固定为 `passed`、`review_required`、`failed`。
3. `parse_quality_status` 是评测结果，不修改 WP-02 `sync_status`、`event_status`
   或 `business_status` 的语义。
4. RAGFlow `DONE` 不等于 `passed`；`DONE` 后仍须通过质量阈值才能判定 `passed`。
5. 阈值通过 `enterprise/scripts/wp03/thresholds.json` 配置，执行时可覆盖。
6. 结果采集只使用 RAGFlow 公共 API，不直接修改 RAGFlow 内部数据库。
7. Phase 1 关键字段 ground truth 由样本生成器同源产生，Manifest 声明
   `ground_truth_provenance.human_reviewed=false`；该结果只作为工程基线，
   不得称为人工标注准确率。人工标注在真实客户样本阶段补齐后再用于验收。
8. 阈值文件记录 `threshold_version`、`phase` 和
   `temporary_conservative`；`min_table_recall=1.0`、
   `min_key_field_accuracy=1.0` 是 Phase 1 临时保守阈值，不是客户验收阈值。
9. `repeatability_hash` 只用于比较同一样本两次 fresh parse 的语义结果，
   排除运行时资源 ID、时间戳、耗时和临时路径；报告环境记录 enterprise commit
   与工作树状态，正式 baseline 只从干净工作树生成，脏工作树必须显式
   `--allow-dirty` 并标记为非正式结果。
   `parse_repeatability_hash` 与 `e2e_repeatability_hash` 分别覆盖解析语义
   和端到端（含 Citation/quality reason）可复现性；基于已保存结果重算时，
   报告必须记录原始解析 Run ID、recompute commit 与 `reparsed=false`。

## 影响

- 后续可把 `parse_quality_status` 持久化到企业侧独立表，不阻塞本阶段报告输出。
- 低质量文档进入 `review_required`，为 Phase 2 人工复核和解析器优化提供依据。
- 现有 WP-02 回归测试不受影响，因为本契约未改变其状态机。
- 页码指标只统计源 PDF 页码范围内的 Position，越界页码计入
  `out_of_range_page_count`，避免掩盖真实空页。
