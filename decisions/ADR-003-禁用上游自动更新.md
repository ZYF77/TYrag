# ADR-003 禁用上游自动更新

- 状态：Accepted
- 日期：2026-08-05
- 决策人：Lead Agent

## 背景

RAGFlow 官方项目包含以下自动更新/自动下载设计：

- `tools/scripts/install.sh` 和 `tools/scripts/install.ps1` 在未显式指定版本时调用 GitHub Releases API 解析 `latest` 并下载安装；
- `docker/entrypoint.sh` 的 `ensure_docling()` 在容器启动时若缺少 docling 则自动从 PyPI 安装；
- `Dockerfile` 构建阶段执行 `ensurepip --upgrade`，自动升级 pip。

企业二次开发需要可复现、可离线、版本冻结的交付基线，不允许运行时或安装时自动拉取最新软件。

## 约束

- 不删除 RAGFlow 源码中与自动更新无关的能力；
- 禁用行为必须可被回归测试检查；
- 所有修改必须登记到 `patches/manifest.yaml`。

## 备选方案

- 保留自动更新但通过配置关闭：仍保留网络依赖和攻击面，不符合版本冻结目标。
- 删除整个安装脚本：安装脚本仍有固定版本安装价值，最小修改更安全。

## 决策

1. `install.sh`/`install.ps1` 不再解析 `latest`，必须显式传入版本号；
2. `entrypoint.sh` 不再自动安装 docling，缺少时直接失败并给出明确错误；
3. `Dockerfile` 移除 `ensurepip --upgrade`。

## 正面影响

- 安装和启动过程不再依赖 GitHub/PyPI 的运行时可达性；
- 镜像构建和部署结果可复现；
- 避免生产环境意外安装新版本组件。

## 负面影响和风险

- 使用默认 `latest` 安装 CLI 的用户会得到明确错误，需要显式指定版本；
- `USE_DOCLING=true` 但镜像未预装 docling 时容器启动失败（失败方式清晰，可提前在镜像构建时预装）。

## 验证方式

- `enterprise/tests/test_no_auto_update.py` 检查四个文件的禁用标记；
- 手动执行 `bash -n`、`sh -n` 和 PowerShell 语法解析（如可用）；
- 构建镜像并启动容器验证 docling 检查逻辑不产生网络请求。

## 回滚方式

撤销 RF-PATCH-001 的四个文件改动即可恢复官方行为；补丁独立于企业功能，可整体重放或删除。

## 对上游升级的影响

升级 RAGFlow 时需重新检查上述文件，若官方恢复自动更新逻辑，需重新应用本补丁。
