# WP-05 设备管理系统 UI 集成与验证界面

## Owner
Frontend Integration Agent

## 目标
正式 UI/用户体验由设备管理系统负责。本工作包冻结并验证其问答、历史、设备上下文、引用、PDF/图片/表格证据、同步状态和复核能力的 Gateway 集成；`enterprise/web` 仅实现 Integration Test Harness、Demo UI 和 Diagnostics UI。

## 依赖
依赖冻结 OpenAPI；后端未完成时使用 MSW/Mock。设备管理系统与 `enterprise/web` 必须消费同一正式契约。

## 交付物

- 设备管理系统 UI 集成说明和验收场景；
- `enterprise/web` 测试、演示和诊断界面；
- 基于角色的集成场景和路由验证；
- SSE 客户端契约验证；
- 引用、文件预览、状态和错误展示验证；
- E2E。

`enterprise/web` 的组件和样式不构成正式客户 UI 产品规范。

## 验收

- 设备管理系统正式 UI 完成普通用户问答、历史、设备上下文、流式回答、引用和必要维护能力集成；
- 普通用户看不到高级配置；
- 401/403/404 不泄漏资源；
- 引用打开前通过 Gateway 重新鉴权；
- 真实状态不伪造百分比；
- SSE 断连正确；
- `enterprise/web` 能在 Mock 和真实 Gateway 模式复现上述契约与失败路径，但不被标记或部署为正式客户前端。

## 禁止修改/禁止范围

不得把 API Key、对象键或管理凭据放入设备管理系统浏览器端或 `enterprise/web`；不得以隐藏按钮替代权限；不得直接调用内部数据库服务；不得将 `enterprise/web` 扩展成设备管理系统的替代品。

## 最小真实联调启动记录（无密钥）

真实联调模式通过环境变量切换，仓库不提交 JWT、RAGFlow API Key、MinIO 密钥或本地运行文件。该模式仅用于 Integration Test Harness、Demo UI 和 Diagnostics UI。

### Enterprise Web

前置条件：RAGFlow 与 Gateway 已在本地运行。

```powershell
$env:VITE_API_MODE = "demo"
$env:VITE_DEMO_JWT = "<运行期注入的本地测试 JWT，不写入源码>"
$env:VITE_DEMO_EXTERNAL_DOCUMENT_ID = "E2E-Doc1"
node node_modules/vite/bin/vite.js
```

环境变量说明：

- `VITE_API_MODE`：`mock|demo|gateway`。`mock` 为默认测试模式；`demo` 使用真实 Gateway demo adapter；`gateway` 用于真实 Gateway 契约联调，均不代表正式客户前端模式。
- `VITE_DEMO_JWT`：运行期 Bearer JWT；仅在 demo adapter 读取，不进入源码、测试快照或日志。
- `VITE_DEMO_EXTERNAL_DOCUMENT_ID`：联调用 externalDocumentId。

### 后端与中间件

- RAGFlow：`cd ragflow/docker; docker compose --profile cpu up -d`。
- Gateway：进入 `enterprise/gateway`，按该目录现有配置启动；密钥从运行环境加载。

页面组件不直接调用 `/demo/*`，demo API 调用集中在 `enterprise/web/src/api/demoClient.ts`。设备管理系统正式 UI 只调用冻结的正式 Gateway API。
