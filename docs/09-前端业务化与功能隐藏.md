# 09 设备管理系统 UI 集成与验证界面边界

## 1. UI 所有权

正式 UI 和用户体验由设备管理系统负责。普通用户从设备管理系统进入知识问答，设备管理系统通过 Enterprise Gateway 集成，不直接暴露内部 API Key，也不直接使用完整 RAGFlow 管理控制台。

`enterprise/web` 的定位固定为：

- Integration Test Harness；
- Demo UI；
- Diagnostics UI。

它不是正式客户前端，不承担生产导航、品牌、最终交互或客户发布责任。RAGFlow 控制台保留给受限管理员和知识维护员。

## 2. 设备管理系统普通用户集成要求

正式 UI 必须覆盖：

- 新会话和历史会话；
- 当前设备/固定资产上下文；
- 问题输入和流式回答；
- 文档引用和业务记录引用；
- PDF 页码定位；
- 图片、流程图和表格预览；
- 无证据、降级和权限提示；
- 会话删除或归档。

Enterprise Gateway 必须提供实现这些交互所需的稳定 API、SSE、状态、错误码和引用模型。`enterprise/web` 可验证同一契约，但其交互不构成设备管理系统的产品规范。

## 3. 维护与诊断集成要求

设备管理系统或其受控运维入口按角色提供：

- 文档同步状态；
- 上游文档 ID、版本和设备关联；
- 当前解析阶段；
- 失败原因和重试；
- metadata 编辑（受控字段）；
- 人工复核；
- 停用/恢复；
- 检索测试；
- 评测问题维护。

`enterprise/web` 可提供对应 Diagnostics UI，供联调、QA 和故障定位使用；不得因此成为生产维护入口。所有操作仍由 Gateway 服务端鉴权和审计。

## 4. 管理能力边界

以下能力由设备管理系统受控管理入口、企业运维工具或受限 RAGFlow 管理控制台承载，不要求在 `enterprise/web` 建设正式后台：

- 用户映射和角色；
- ACL 策略测试；
- RAGFlow dataset/chat 资源映射；
- 模型和 parser profile；
- 同步任务和积压；
- 备份、运行状态和升级信息；
- 审计日志。

## 5. 不向普通用户暴露

- Agent Canvas；
- Browser、MCP、Sandbox、Code Executor；
- Deep Research、联网搜索；
- GraphRAG、RAPTOR、PageIndex 高级选项；
- Memory 管理；
- Embedding/Reranker/Chunk 参数；
- 文档引擎和对象存储入口；
- API Key、内部 URL、对象键；
- 直接删除底层对象和索引。

设备管理系统正式 UI 和 `enterprise/web` 均须遵守以上暴露边界。隐藏仅用于减少复杂度，不能替代后端授权。

## 6. 进度语义

设备管理系统必须按 Gateway 返回值区分：

```text
上传/登记完成
等待处理
解析中
索引中
待复核
可查询
失败
已停用
```

任何 UI 都不得用定时器伪造解析百分比。若 RAGFlow 只能提供阶段状态，则显示不确定进度和真实阶段，不编造数字。

## 7. 引用展示与访问

设备管理系统的引用视图默认可折叠，展开后展示：

- 来源类型；
- 文档名或业务记录；
- 版本和页码；
- 命中片段；
- 图片/表格缩略图；
- “定位到原文”；
- 来源有效状态。

引用打开时必须通过 Gateway 重新鉴权，不能信任会话历史中的旧 URL。`enterprise/web` 的引用组件用于验证这一集成契约和错误路径。
