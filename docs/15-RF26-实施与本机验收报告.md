## WP07 阻塞与复跑边界

Docker restart/recreate 权限已恢复，本机 MySQL、Redis、MinIO、ES、RAGFlow 与 Gateway 已启动并加载当前代码。DeepDOC 缺失的官方 `updown_concat_xgb.model` 已下载到仓库忽略的本机运行目录，并按官方 SHA-256 `50516159cd0aab5f3499e1edccffdf1d6141f5ae513fdba003a18cbefa823f62` 校验。

测试结束后已重新创建 Gateway 以清除进程内一次性 callback secret/endpoint；当前 Gateway health 通过，临时 callback 配置已关闭。

`20260824T013519Z` 轮次真实通过了官方上传/解析/质量、callback 重试、两轮 JSON/SSE/history、citation source 及三个负例，原失败点是宿主 runner 在 Gateway 运行时直接读取 bind-mounted SQLite session 映射。该断言已改为 RAGFlow 官方 `GET /chats`、`GET /chats/{id}/sessions` 与 `GET /chats/{id}/sessions/{session_id}`，并用当轮会话完成定点检查。

后续全量复跑的新文档在绑定 embedding 模型时失败：RAGFlow 容器既不能解析默认 `dashscope.aliyuncs.com`，也不能解析当前已配置的 embedding 域名；同一配置在 09:35～09:46 的早先轮次曾成功。当前最小复跑路径是：

1. 先确认 RAGFlow 容器可解析并访问已配置 embedding 服务；
2. 若本机服务仍在运行，无需再次重启容器；只用当前一次性 callback 配置运行 `enterprise/scripts/run_file_share_v3_v2_e2e.py`；
3. 只有 `summary.json`、`acceptance.md`、`requests.ndjson`、`callback-evidence.json` 在同一轮全部通过，才把 WP07 改为完成。

禁止把离线 P0、容器单测或 health 结果替代真实 HTTP E2E；禁止连接或部署 30 服务器。
