## M3 晋级所需的完整证据

本任务不实现下列功能；它们是未来从当前状态进入 M3 Beta 评审的硬门槛：

- **M3-A**：客户只读 DB schema、driver、连接池和 ACL resolver；真实 PG/TimeSeries 集成及越权负向证据。
- **M3-B**：subscriber/callback 注册与授权、key rotation、delivery/outbox、DLQ/replay 和 observability contract/evidence。
- **M3-D**：dense/sparse provider 接口、score 语义、RAGFlow/backend 接线、ACL 事实归属和评测阈值。
- **M3-E**：batch API、review 权限、断点恢复和多实例 repository/locking 证据。
- **M3-F**：真实负载、限流 enforcement point、性能目标、备份/恢复和监控告警演练。
- **M3-G**：attachment/assetId/expiry/error code freeze，以及真实设备管理系统 UI ↔ Gateway ↔ Asset Registry 证据。

所有上述门槛都必须保留可审计的命令、环境版本、非敏感证据路径和权限负向结果；不得以 offline pass、MSW/mock、memory、skip 或 xfail 替代。

## Runner 报告语义

`enterprise/scripts/run_enterprise_tests.ps1` 的 profile 选择和退出码不变：

- `Contract`：只跑 Contract 静态门禁；
- `P0` / `Integration` / `WP03` / `All`：包含离线 `pytest-offline` implementation tests；
- `Integration` / `All`：另跑 live preflight 和 FILE_SHARE v3 + formal v2 E2E；缺少 live 环境仍为 exit 3；
- runner 报告必须写明“存在离线 implementation tests，但没有 M3 live Integration evidence”；离线测试通过不能把 M3 Beta 改写为 accepted。

本状态矩阵不改变 Contract、P0 或 Integration 的测试选择、环境变量和退出码语义。
